# Implementation status

The `0.4.0-preview.1` implementation contains **43 diagnostics**, five compiler analyzers, a reusable Core engine, five report formats, and six NuGet packages. This page records the implemented mechanism and the boundary of each claim. It describes the current source and package payloads; ordinary C# retains its own language and runtime semantics.

## Validation checkpoint

At source checkpoint [`66ae53d`](https://github.com/wieslawsoltes/SafeSharp/commit/66ae53da165fae4dc08034bc3da1e08fd9474ea2), [CI](https://github.com/wieslawsoltes/SafeSharp/actions/runs/39428653978) passed **2,490 tests on each of Linux, Windows and macOS**, with **zero failures and zero skips**. Release builds reported zero warnings and errors. The CLI integration suite, benchmark verification, six-package checks, clean current-SDK consumers and the minimum Roslyn 4.14 package host also passed. These results apply to that pinned checkpoint; subsequent documentation/configuration commits require their own CI run. The earlier 2,268-test result is historical.

## Deliberate precision boundaries

These limitations remain material when interpreting a clean report. “Supported” always means the represented facts, recognized operations and declared contracts described in the corresponding guide.

| Area | Supported now | Remaining boundary |
| --- | --- | --- |
| C# semantics | Explicit moves, loans, resource identities and contract validation. | Annotations do not revoke CLR references or create move-only types. The C# compiler owns definite assignment, ref safety and built-in language restrictions. |
| External behavior | Known framework effects and source/metadata contracts. | Unknown virtual/native/reflection/dynamic behavior can introduce unmodeled effects or aliases. No arbitrary heap-separation or whole-program proof is claimed. |
| Source and reference summaries | Exception/filter/finally routing, returned storage, canonical aggregate cells, ref/out locations and modeled normal-exit postconditions. Captured writable aggregate-ref locations are weakened on exceptional exits before filters and cleanup. | Arbitrary callbacks, recursive/virtual effects and external ref-slot postconditions remain opaque. Exceptional weakening does not reconstruct a callee's exact write history or invent replacement ownership. Source-inference exhaustion yields an opaque summary. |
| Borrowed escapes | Converged provenance through represented aliases, containers and captured storage. | Allocation containers merge fields/elements; handler and mutable-capture histories remain conservative envelopes. Unknown calls establish neither general retention nor freshness. The newer source-summary router does not turn this separate domain into a full heap-shape analysis. |
| Async carriers | Up to 16 Task/ValueTask result layers, represented payload identity, actual custom awaiter contracts and modeled completed producers. | Unknown/custom builders, opaque transforms and awaiter internals need trustworthy contracts. Task identity alone is not payload provenance or completion readiness. |
| Task compositions | Exact framework WhenAll/WhenAny/Unwrap/WaitAsync over represented task arguments, arrays and supported span/collection expressions. Canonical element refs preserve cache coherence; opaque effects and exceptional writable-ref exits weaken contents while preserving independent values and captured composition inputs. | Arbitrary IEnumerable/custom collections, unknown spans/spreads, ContinueWith and scheduling callbacks remain external. Dynamic indexing/foreach does not prove complete result coverage, and concurrent array mutation is not modeled. Summaries retain terminal provenance rather than an arbitrary composition graph. |
| ValueTask | Single-consumption capability identity, alias/join/transfer checks and reusable AsTask/Preserve results. | General IValueTaskSource internals, completion readiness and unknown unannotated consumers are not proven. A clean consumption result does not prove successful execution or physical cleanup. |
| Cleanup | Recognized release invocation and separate asynchronous observation; aggregate obligations at modeled normal exits. | Throwing cleanup can partially release runtime resources. The model does not prove physical cleanup after arbitrary exceptional termination or cross-call object invariants. |
| Lifetime/type system | Explicit nested binders, placeholder visibility, corresponding TypeLifetime paths, declared variance, scoped type bounds and supported implied input/owner bounds. Direct calls check those requirements against declared caller facts and stable parameter/local-alias evidence. | Nested contents remain trusted contracts. Mutated or unknown evidence, arbitrary factory/conditional results, nominal projection conversions and unannotated callback generalization cannot supply a proof. No full trait solver, arbitrary object-content body proof or Rust-complete type inference is claimed. |
| Concurrency | Explicit Send/Sync composition and sequential guarded-access/lock/semaphore protocols. Binary SemaphoreSlim permits are not thread-affine; a Task observation grants at most its one represented acquisition. GuardedBy does not relax the existing Sync structural requirements. | No Rust auto traits, arbitrary synchronization discovery, scheduler/thread interleaving proof, deadlock-freedom proof, general race freedom, atomic ordering or native memory model. Unknown semaphore maxima cannot establish exclusive access; custom wrappers and external signaling/release patterns need additional contracts. |
| Allocation and heap | Static projections, canonical aggregate element/ref storage, captured-address liveness and finite allocation sites. | General symbolic index inequalities, heap shape, arbitrary collection ownership and concrete per-iteration allocation counts are not solved. Loop aggregate caches can require weak updates. Storage coherence does not derive child loans from an array loan or propagate parent borrowing permissions through captured element refs. |
| Unsafe and addresses | Optional auditing of unsafe/dynamic boundaries. | Pinning, self-referential state-machine validity, raw-pointer provenance, UnsafeCell, stacked/tree borrowing and address stability remain outside the analysis. |

## Incompleteness is observable

SS0015 identifies ownership-flow/domain limits; SS0029 identifies service exploration limits; SS0043 identifies lifetime solving, nested type comparison and return-provenance limits; SS0046 identifies cleanup, concurrency, synchronization and borrowed-escape contract limits. The CLI returns exit code 2 for an incomplete configured analysis even when these diagnostics are suppressed or `--fail-on none` is used. A solver budget is not a successful verification. Internal source-summary fallback retains unknown provenance; it cannot supply a proof that the unavailable summary would have established.

Adding another mechanism requires a defined transfer or contract rule, valid and invalid C# regressions, evidence/report support where applicable, and an update to this support boundary. Broader safety claims need demonstrated coverage and an explicit account of remaining approximations.
